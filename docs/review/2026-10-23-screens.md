# Review notes, screens, 23 October 2026

**S-37. Recheck requires a later confirmed master-list upload.** The check pane previously
treated every version mismatch as a master-list replacement. Legacy invoices checked
against the file-based sheet therefore showed "The master list has changed" even when
the uploaded master list predated the invoice and no replacement had been saved.
`hasNewerMasterList` in `src/checker/review.ts` now requires a completed live invoice,
known differing versions, and a master-list upload timestamp later than the invoice's
upload timestamp. Missing or invalid dates do not establish a newer master list.
Opening or canceling replacement, including canceling after file preview, does not
create a new version or trigger the prompt. Existing invoice results are preserved.

passed. Full `npm run lint` could not scan `backend/.pytest_cache` due to an EPERM
directory permission error. Chrome verified a legacy version mismatch stays hidden,
canceling without a file stays hidden, canceling after preview stays hidden, and a
confirmed newer replacement shows the recheck button, with no page errors. Browser
checks used invented records and intercepted API writes; the active master list and
invoice records were unchanged.
